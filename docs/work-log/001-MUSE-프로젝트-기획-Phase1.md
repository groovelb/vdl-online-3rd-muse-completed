# 001. MUSE 프로젝트 기획 Phase 1 (project-summary) 작성

## 🎯 의도 (User Goal)

> 사용자가 MUSE(레퍼런스 기반 디자인 토큰 추출 도구)의 개요·문제 인식·기능 범위 초안을 `/project-planning` 스킬로 넘겨, Phase 1 `project-summary` 문서를 템플릿에 맞춰 작성하고자 함.

## 🔑 주요 의사결정

- **기획 문서를 `docs/muse/` 하위에 배치**: 프로젝트별 폴더로 분리해야 향후 ux-flow/visual-direction과 함께 세트로 관리 가능하기 때문.
- **핵심 기능을 표로 정리 + 우선순위 `필수/선택` 2단계**: 템플릿 규칙을 따랐고, MVP 범위를 명확히 하기 위함.
- **"자동 태깅"을 `필수`로, "자동 추천"은 `선택`으로 분리**: 태깅은 아카이빙 UX의 근간이라 MVP 필수, 추천은 수동 선택으로 대체 가능해 MVP 스코프 팽창 방지.
- **스코프 `제외` 항목을 명시**: 코드 생성·협업 기능·모바일 네이티브·MUI 외 포맷을 제외해 스코프 크립 차단.
- **성공 기준에 "자동 태깅 + 레퍼런스 자동 탐색" 추가**: 사용자 요청으로 반영, 이후 동일 내용을 핵심 기능 표에도 중복 반영해 성공 지표와 기능 정의를 일치시킴.

## 💬 Claude의 핵심 반응

- 초안 작성 후 **확인 포인트 4개 제시**(저장소 전략/AI 모델/유형 프리셋 우선순위/타이포 분석 범위) — 결정 유보 지점을 명시적으로 드러내 Phase 2 전에 해소되도록 함.
- 사용자가 "성공 기준에 자동 태깅/추천 추가" 요청 시, **성공 기준(결과 지표)과 핵심 기능(범위)을 구분**하고 양쪽에 각각 반영하되 우선순위를 나눠 제안.
- Phase 2(ux-flow) 진행 전 승인 게이트 유지 — skill 원칙에 따라 승인 없이 다음 Phase로 넘어가지 않음.

## ✅ 최종 결과

`docs/muse/01-project-summary.md` 작성 완료, Phase 1 승인 대기 상태. 핵심 기능 8개(필수 6 + 선택 2), 성공 기준 4개 확정.

## 🔁 재현 가이드 (교육생용)

1. Claude에게 `/project-planning` 호출 + MUSE 개요/문제인식/기능범위 초안을 arguments로 전달.
2. Claude가 `.claude/skills/project-planning/resources/doc-templates.md`를 Read해 `project-summary` 템플릿 구조 확인.
3. `docs/muse/` 폴더 부재 확인 → `docs/muse/01-project-summary.md` Write로 작성 (배경·핵심기능 표·대상사용자·기술적 범위·성공 기준).
4. Claude가 승인 게이트에서 확인 포인트(저장소/AI모델/유형프리셋/타이포)를 함께 제시 → 사용자가 수정 요청.
5. 수정 요청은 `Edit` 도구로 섹션 단위 반영 (전체 재작성 X): 성공 기준 추가 → 핵심 기능 표에 태깅/추천 항목 추가.

> 💡 핵심 포인트: Phase 1은 **승인 없이 Phase 2로 넘어가지 말 것** — 초안 → 확인 포인트 제시 → 수정 반영 → 명시적 승인의 순서를 반드시 지킨다. 성공 기준과 핵심 기능은 성격이 다르므로(결과 지표 vs. 범위 정의) 같은 내용이라도 양쪽에 맞게 구분해 표현한다.
